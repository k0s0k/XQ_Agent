# 心桥 · XQ Agent

一个面向**心理咨询师辅助接诊**的本地工作台。可以直接与大模型对话、检索自己的知识库，也可以整理接诊记录、使用量表和导出摘要。

## 功能

| 功能       | 使用方式                                                                       |
| ---------- | ------------------------------------------------------------------------------ |
| 主对话     | 配置模型后直接提问，保留当前运行期间的多轮对话                                 |
| Top K 检索 | 每轮匹配最相关的 1–10 篇知识文档，展示排名、片段、相关分数和来源；默认 5 篇    |
| 本地知识库 | 导入 TXT、Markdown、DOCX、文字型 PDF，也可粘贴文本；支持预览、启用、停用和删除 |
| 辅助接诊   | 记录主诉和咨询师笔记，使用 PHQ-9 / GAD-7，整理并导出 Markdown 摘要             |

知识库使用本地 BM25 文本检索，不需要向量数据库或 Embedding 服务。Top K 按文档去重，相关结果不足 K 篇时只显示实际命中结果。

## 快速启动

准备 **Node.js 22.19 或更新版本**、**pnpm 11**。在 PowerShell 中执行：

```powershell
cd XQ_Agent
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开 [http://127.0.0.1:4320](http://127.0.0.1:4320)。退出服务时按 `Ctrl+C`。

修改代码时使用 `pnpm dev`，打开 [http://127.0.0.1:5174](http://127.0.0.1:5174)，页面会自动更新。开发模式和正式运行模式会占用同一个后端端口，运行其中一种即可。

## First使用

1. 点击页面中的“模型设置”，填写服务地址、模型名称和 API Key。
2. 打开“知识库”，导入自己准备的参考资料。每份文档默认仅用于本地检索。
3. 回到“主对话”，设置 Top K，启用知识库检索，输入问题。
4. 如需调用模型，在当前对话中允许外部模型处理；如需让模型引用某份资料，还需在知识库中允许该文档发送给模型。
5. 需要接诊时打开接诊工作台，建立记录，填写主诉、笔记和量表，最后导出摘要。

未配置模型或未开启对话授权时，仍可使用知识库、量表和本地记录；主对话会明确提示未调用大模型。检索结果会区分“仅本地展示”和“已提供给模型”。

## 模型配置

页面中填写的模型设置只保存在本次服务内存中。希望重启后继续使用时，将 `.env.example` 复制为 `.env`，再填写：

```dotenv
XQ_BASE_URL=https://your-provider.example/v1
XQ_MODEL=your-model-name
XQ_API_KEY=your-api-key
XQ_PORT=4320
```

使用兼容 Chat Completions 的模型服务。服务地址通常以 `/v1` 结尾；远程地址使用 HTTPS，本机模型可使用 HTTP。密钥由后端读取，不会写入前端构建文件。

可通过 `XQ_KNOWLEDGE_DIR` 指定知识库存放目录；未设置时使用项目内的 `.local/knowledge`。

## 数据保存

- **会话、接诊记录、笔记、量表和页面填写的密钥**：保存在服务内存中，重启后清除。需要保留的接诊内容请先导出摘要。
- **知识文档及其权限**：保存在本机 `.local/knowledge/knowledge.json`，重启后仍可使用。
- **模型调用**：只有完成模型配置并取得当前会话授权才会发送；知识片段还需该文档单独允许发送。更换模型服务地址会撤销会话授权。
- **版本提交**：`.env`、`.local`、`node_modules`、`dist` 均已加入忽略规则，避免提交密钥、私人资料和生成文件。

当前版本供本机单人使用，默认只监听回环地址。它提供咨询辅助，不替代专业判断；量表分数是筛查结果，不是诊断。

## 项目结构

```text
XQ_Agent/
├── src/
│   ├── client/          # React 页面、组件、样式和 API 调用
│   │   ├── api/         # 请求封装和接口类型
│   │   ├── components/  # 通用弹窗、Markdown 等组件
│   │   ├── features/    # chat / knowledge / intake / settings
│   │   ├── styles/      # 应用通用样式
│   │   └── utils/       # 错误处理、来源地址校验
│   ├── server/          # HTTP 服务、模型调用、文档解析和知识检索
│   └── shared/          # 前后端共用的量表定义与计分
├── tests/               # 后端接口、检索、文件解析和量表测试
├── scripts/             # 开发、启动和环境变量加载脚本
├── docs/                # 架构、知识库和临床来源说明
├── .env.example         # 本地配置模板
├── package.json         # 项目依赖与命令
└── README.md            # 使用入口
```

组件文件使用 `PascalCase.tsx`，普通 TypeScript 模块使用 `camelCase.ts`，后端和脚本文件使用 `kebab-case.mjs`，环境变量统一为 `XQ_*`，样式类统一为 `xq-*`。前后端接口统一位于 `/api`。

## 常用命令

| 命令                        | 用途                                               |
| --------------------------- | -------------------------------------------------- |
| `pnpm dev`                  | 同时启动前端开发服务和后端                         |
| `pnpm build` / `pnpm start` | 构建页面 / 启动完整应用                            |
| `pnpm api`                  | 启动后端，无需预先构建页面；已有 dist 时也提供页面 |
| `pnpm test`                 | 运行功能测试                                       |
| `pnpm typecheck`            | 检查 TypeScript 类型和未使用的声明                 |
| `pnpm format`               | 统一代码格式                                       |
| `pnpm check`                | 一次执行格式检查、类型检查、测试和构建             |

运行报端口占用时，先停止该项目已有的服务，或修改 `.env` 中的 `XQ_PORT`。扫描件 PDF 需要先转换为可复制文字的文档，本项目不包含 OCR。

更多说明见 [架构与开发说明](docs/architecture.md)、[知识库与 Top K](docs/knowledge-base.md)、[量表与临床来源](docs/clinical-notes.md)。项目许可及必要的来源说明见 [LICENSE](LICENSE) 和 [NOTICE.md](NOTICE.md)。
