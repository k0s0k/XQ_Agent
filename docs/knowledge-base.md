# 主对话与 RAG 知识库

心桥提供独立主对话和本地知识库。主对话可直接向已配置的 LLM 提问，也可先检索资料，再把获准使用的片段交给模型辅助回答。

检索使用中文 BM25，不依赖外部数据库或向量服务。目前不包含向量语义检索、模型重排或 OCR。知识文档由使用者主动导入，系统不会读取其他项目的数据或配置。

## 导入和核对资料

1. 打开“知识库”，上传 UTF-8 TXT、Markdown、DOCX 或带文字层的 PDF，也可以直接粘贴文本。
2. 填写便于辨认的标题和原始来源链接。链接仅用于来源标注，系统不会访问该地址。
3. 查看提取后的正文，核对阅读顺序、段落、表格和关键表述。
4. 在检索预览中输入具体问题，检查命中的资料是否相关。

扫描 PDF 需先自行完成 OCR；不支持旧版 `.doc`、加密文件或网页抓取。导入的资料需要使用者审核，上传成功不代表内容已经过医学核验。

## 在主对话中使用 Top K

1. 新建主对话，开启知识库检索。
2. 选择 Top K，默认 5，可选 1–10，然后发送问题。
3. 在“相关文档”中查看排名、文档标题、匹配分、最相关片段和来源链接；可打开正文进一步核对。
4. 选择历史回答，查看那一轮的来源快照。修改当前 K 不会改变历史结果。

主对话按**不同文档**计算 K：先为所有片段计算匹配分，每份文档保留最高分片段，再取前 K 份文档。长文档不会因为片段多而占满结果；没有相关内容时返回零命中，不用无关文档补足 K。

BM25 分数只用于当前问题的关键词相关性排序，不是置信度、临床正确率或百分比，也不适合跨问题比较。接诊对话保留片段级检索，知识库检索预览也可使用片段模式。

## 哪些资料会交给模型

每份文档导入后默认启用本地检索，默认**禁止外发**。只有以下条件同时满足，命中的片段才会交给模型：

- 已配置模型服务地址、模型名称和密钥。
- 当前对话或接诊会话已同意将内容发送给该模型提供方。
- 当前会话已开启知识库检索。
- 文档仍启用，且已开启“允许向模型发送片段”。

没有模型配置或会话同意时，仍可本地检索。主对话会明确显示没有调用 LLM；接诊模式的本地规则提示也不会被标成根据资料生成的回答。

主对话只会发送本轮 Top K 中获准外发的片段。例如匹配到 `[K1]`、`[K2]`、`[K3]`，只有第二份获准外发，模型只收到 `[K2]`；系统不会从排名 K 以外补充文档。界面会区分“仅本地展示 · 本轮未发送”和“已提供给本轮模型”。

知识库关闭后，获准调用的模型仍可直接回答。紧迫危险线索优先进入本地安全提示流程，不调用模型或知识库生成建议。

## 保存、撤回和引用

知识库默认保存在 `.local/knowledge/knowledge.json`；可通过 `.env` 中的 `XQ_KNOWLEDGE_DIR` 修改位置。一个目录只供一个服务进程写入。原始上传文件、检索问题、会话记录和模型密钥不会写入该知识库文件。

停用、删除文档或撤回外发权限后，未来请求不再使用它，并取消相关进行中的模型请求。引用过该文档以及间接依赖它的助手历史消息也会从后续模型上下文中排除。已经送达外部服务的数据无法从本机撤回。

历史回答保留当时的来源快照；删除文档不会删除已存在的会话快照。删除该会话或停止服务可清除这些内存记录。模型接收的资料被标为参考数据，不能覆盖系统角色；无效的引用编号会被标为来源未核实，但系统无法自动证明每个观点都被原文支持。

## 文件和检索限制

| 项目         | 限制或实现                                            |
| ------------ | ----------------------------------------------------- |
| 单个上传文件 | 最多 5 MiB                                            |
| 单份提取正文 | 最多 20 万字符                                        |
| PDF          | 最多 200 页，仅提取文字层                             |
| 知识库       | 最多 100 份文档、合计 500 万字符                      |
| 分块         | 目标约 900 字符，重叠约 120 字符                      |
| 中文检索     | `Intl.Segmenter` 分词、双字组合、停用词过滤及标题加权 |
| 持久化       | 本地 JSON，写入排队并以原子替换保存                   |

DOCX 使用 fflate 解析，PDF 使用 PDF.js 提取文字。二进制解析在工作线程中执行，设有超时和资源限制；图片、复杂表格、脚注和多栏版式仍需人工核对。关键词检索可能漏掉同义表达、跨语言内容和需要复杂推理的问题。

## API 示例

接口均以 `/api` 开头。

| 方法与路径                        | 请求或用途                                                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/knowledge`              | 文档元数据和存储状态                                                                                                                   |
| `POST /api/knowledge`             | 文本：`{title, content, source?, enabled?, allowExternal?}`；文件：`{filename, dataBase64, title?, source?, enabled?, allowExternal?}` |
| `GET /api/knowledge/:id`          | 提取正文                                                                                                                               |
| `PATCH /api/knowledge/:id`        | 修改标题、来源、启用或外发权限                                                                                                         |
| `DELETE /api/knowledge/:id`       | 删除文档及索引                                                                                                                         |
| `POST /api/knowledge/search`      | `{query: "问题", unit: "documents", limit: 5}`，按文档检索                                                                             |
| `POST /api/sessions`              | `{kind: "chat", name: "新对话", topK: 5, useKnowledge: true, consent: false}`                                                          |
| `PATCH /api/sessions/:id`         | 更新 `topK`、`useKnowledge` 或 `consent` 等会话设置                                                                                    |
| `POST /api/sessions/:id/messages` | `{content: "问题"}`，返回会话及本轮来源                                                                                                |

检索预览省略 `unit` 时按片段检索，`limit` 可选 1–20；`unit: "documents"` 时可选 1–10。助手消息的 `knowledge` 记录本轮请求数量、命中文档数及实际提供给模型的文档数，每条来源的 `providedToModel` 标明是否实际交给模型。

运行 `pnpm test` 可验证检索、解析、权限过滤、来源快照、持久化和模型上下文行为。模型测试使用模拟响应，不代表真实提供方的回答效果。
