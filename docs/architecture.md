# 项目结构与开发说明

心桥（XQ Agent）是面向心理咨询师的本机工作台。前端负责主对话、接诊记录和知识库管理；Node.js 服务负责检索、模型请求、量表校验和会话管理。项目可独立安装和运行。

## 目录职责

| 位置                               | 内容                                |
| ---------------------------------- | ----------------------------------- |
| `src/client/`                      | React 页面、组件、样式和 API 客户端 |
| `src/server/app-server.mjs`        | HTTP 接口、会话管理与静态页面服务   |
| `src/server/http-utils.mjs`        | 输入校验、HTTP 错误和请求体读取     |
| `src/server/model-provider.mjs`    | 模型请求、取消和来源权限过滤        |
| `src/server/assistant-prompts.mjs` | 提示词、本地演示回复和接诊纪要      |
| `src/server/safety-rules.mjs`      | 本地风险识别和安全提示              |
| `src/server/knowledge-store.mjs`   | 文档保存、分块和 BM25 检索          |
| `src/server/document-parser.mjs`   | TXT、Markdown、DOCX 和 PDF 正文提取 |
| `src/shared/assessments.mjs`       | 前后端共用的量表题目、来源和评分    |
| `tests/server/`、`tests/shared/`   | 服务、检索、解析和量表测试          |
| `scripts/`                         | 环境配置读取、开发和生产启动脚本    |
| `docs/`                            | 架构、知识库与临床使用说明          |

文件名采用有明确含义的英文名称：React 组件使用 `PascalCase.tsx`，服务和脚本使用 `kebab-case.mjs`，变量与函数使用 `camelCase`。环境变量使用 `XQ_` 前缀，页面样式使用 `xq-` 前缀。通用组件独立存放，避免业务组件循环引用主页面。

## 一次对话

1. 前端将本次输入发送到 `/api/sessions/:id/messages`。
2. 服务先检查会话、输入和本地风险规则。紧迫危险线索优先返回安全提示，不等待模型生成。
3. 开启知识库时，根据最新输入执行本地检索。主对话返回最多 K 份不同文档；接诊对话使用片段级检索。
4. 模型已配置且当前会话同意外发时，服务将本次输入、该会话近期消息及允许外发的资料片段交给模型。接诊会话还会纳入其已保存的主诉、笔记等背景；主对话不会读取其他会话或个案资料。
5. 服务返回回答、实际生成方式和本轮来源快照，前端据此展示回答与相关文档。

主对话缺少模型配置或授权时，会明确提示未调用 LLM，并可继续展示本地检索结果。接诊模式可提供独立的本地规则提示。模型回答、规则提示和安全提示分别记录为 `llm`、`local`、`safety`。

## 配置\数据

启动脚本读取项目根目录的 `.env`，示例见 `.env.example`。默认生产页面与 API 地址为 `http://127.0.0.1:4320`，开发页面为 `http://127.0.0.1:5174`。

| 变量               | 用途                                    |
| ------------------ | --------------------------------------- |
| `XQ_BASE_URL`      | Chat Completions 兼容服务的基础地址     |
| `XQ_MODEL`         | 模型名称                                |
| `XQ_API_KEY`       | 模型服务密钥                            |
| `XQ_PORT`          | 本机 API 及生产页面端口，默认 4320      |
| `XQ_KNOWLEDGE_DIR` | 知识库保存目录，默认 `.local/knowledge` |

主对话、接诊记录和在页面填写的模型配置只保存在服务进程内存中；刷新页面不会清除，停止或重启服务会清除。`.env` 中的配置由使用者保存在本地文件中，启动时重新加载。知识库正文单独保存在本地 JSON 文件中，重启后保留；原始上传文件不另外保存。

模型密钥不从读取配置接口返回，也不写入浏览器 `localStorage`。更换模型服务地址会撤回所有会话的外发同意；撤回会话同意或文档外发权限会取消相关进行中的请求。已发送给外部服务的数据无法从本机撤回。

服务仅监听本机，并检查请求来源。当前没有机构多账号、角色权限或操作审计，不能直接当作多人生产服务开放到公网。

## 接口概览

业务接口统一使用 `/api` 前缀。

| 路径                         | 用途                           |
| ---------------------------- | ------------------------------ |
| `/api/status`                | 当前模型配置与运行状态         |
| `/api/settings`              | 读取或修改模型配置，不返回密钥 |
| `/api/sessions`              | 列出或创建主对话、接诊会话     |
| `/api/sessions/:id`          | 读取、修改或删除会话           |
| `/api/sessions/:id/messages` | 发送消息并获取回答             |
| `/api/knowledge`             | 列出或导入知识库文档           |
| `/api/knowledge/:id`         | 查看正文、修改权限或删除文档   |
| `/api/knowledge/search`      | 本地检索预览                   |

主对话使用 `kind: "chat"`，接诊使用 `kind: "intake"`。具体知识库请求示例见 [知识库说明](knowledge-base.md)。

## 开发与验证

从项目根目录执行：

```powershell
pnpm dev          # 同时启动 API 与前端热更新
pnpm format       # 统一代码和文档格式
pnpm typecheck    # TypeScript 检查
pnpm test         # 自动化测试
pnpm build        # 生成 dist/ 生产页面
pnpm check        # 格式、类型、测试和构建的完整检查
```

测试使用隔离的临时目录和模拟模型响应，不需要真实模型密钥。测试关注权限撤回、来源追踪、输入边界、中文检索、文件解析、量表评分等行为。真实模型的输出质量仍需配置服务后由咨询师复核。
